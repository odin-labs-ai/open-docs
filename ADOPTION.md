# Beginner adoption decisions

Role-based AI adoption consultation for this iteration; no private specialist profile was available. The design recommendation is a short guided workshop alongside the existing advanced course. A light theme can reduce visual intensity, but the main intervention is reducing simultaneous decisions: one task, one visible next action, and an observable consequence.

Each exercise should ask the learner to predict, act, observe, explain and transfer. The five connected ideas are a precise task contract, relevant context, scoped tool execution, independent verification, and recovery from uncertain state. The existing advanced course remains the place to investigate deeper mechanisms and vocabulary.

The stage should explain causality. Context selection changes which evidence enters the model. A denied proposal stops before the tool boundary. An accepted action produces an artifact. A failed check routes back to correction. A restart restores a checkpoint and revalidates current state. Repeating ambient motion carries little educational information; pause and step should preserve every meaningful state in readable text.

Provider choice is a transfer lens. Codex, Claude Code and Droid have different project and execution configuration; Pi is an extensible harness with no built-in permission popups. DeepSeek supplies a model within a host such as Pi. Changing the provider should change concrete entry guidance, while the task contract and acceptance evidence stay stable. Public examples use a downloaded fictional fixture.

The first useful multimedia additions are visual evidence and optional narration with visible transcripts. Video belongs beside a specific concept and should be user initiated. Three.js is the spatial renderer; browser media elements, audio APIs handle their respective responsibilities. VR is a later option if a concrete spatial learning task justifies it.

## Beginner acceptance checks

- A fresh visitor can identify what to do next without inspecting the advanced lesson index.
- The learner must make a prediction and run a changed configuration; merely opening text does not prove understanding.
- The same action produces matching stage, trace and artifact outcomes, including the failed path.
- A wrong explanation gives a causal reason and a retry; completing the visible exercise requires explaining the result.
- Keyboard, reduced-motion and WebGL-fallback users can observe every required state and complete the same task.
- The starter fixture fails before the typo correction, passes after the exact correction, and fails if the link or target changes.
- Switching entry examples exposes actual tool/instruction distinctions and keeps the shared contract.

Browser tests can establish that the intended learning interactions work. They cannot establish that a human beginner has learned the subject. A later facilitated session should ask a new learner to repair a changed fixture without hints, explain which component enforces scope, and name the evidence they used.
